Setiap alur generate WAJIB punya layar konfigurasi sebelum generate. Konfigurasi minimal meliputi:

- output format: DOCX, PDF, PPTX, plain text, visual preview
- bahasa dokumen: Indonesia / English
- target region: Indonesia / Global / US / UK / custom
- tone: formal, warm, confident, concise, persuasive, academic, professional
- panjang output: jumlah kata, jumlah halaman, jumlah slide, jumlah paragraf, jumlah bullet

- margin jika relevan
- section include/exclude
- section order
- jumlah item yang ditampilkan per section
- tingkat kreativitas model
- strictness anti-hallucination
- evidence requirement: wajib angka/bukti, boleh naratif, atau balanced
- target job/org/scholarship context
- additional instruction dari user
- export filename
- apakah output disimpan sebagai versi baru atau menimpa versi lama

Buat tipe data terpusat, misalnya GenerationConfig atau DocumentGenerationConfig. Simpan konfigurasi yang dipakai pada setiap dokumen/output agar user bisa:

- melihat konfigurasi lama
- clone konfigurasi
- regenerate dengan konfigurasi sama
- mengubah sebagian konfigurasi
- membandingkan versi output

Pastikan konfigurasi ini tidak hanya UI palsu. Konfigurasi harus benar-benar memengaruhi prompt, renderer, export, layout, word count, slide count, dan validasi output.

Jika user meminta 10 halaman, 10 slide, 1500 kata, atau format tertentu, sistem harus mencoba memenuhi secara realistis. Jika permintaan tidak masuk akal, tampilkan warning yang ramah, misalnya: “CV ATS 10 halaman berisiko tidak efektif untuk early-career. Tetap lanjut atau ubah ke 1–2 halaman?”

Pastikan semua konfigurasi tetap tunduk pada prinsip BRIEF.md:
- edit-before-generate wajib
- verifikasi sebelum generate wajib
- jangan mengarang detail personal
- semua klaim harus bisa ditelusuri ke UserProfile/context_notes/probing answer

TAMBAHAN WAJIB — GENERATED ARTIFACT QA & RENDER VALIDATION

Audit semua fitur yang menghasilkan artifact/output, termasuk CV ATS, CV Visual, resume, cover letter, bio, essay, personal deck PPTX, DOCX, PDF, English practice, listening audio, application summary, dan interview answer.

Jangan hanya mengecek bahwa file berhasil dibuat. Wajib cek hasil generate secara nyata dari sisi isi, konfigurasi, render, dan usability.

Untuk setiap artifact yang dihasilkan, jalankan validation pipeline:

1. CONFIG-TO-OUTPUT VALIDATION
Pastikan output benar-benar mengikuti konfigurasi user:
- jumlah halaman sesuai atau mendekati target
- jumlah slide sesuai target
- jumlah kata sesuai target
- jumlah paragraf sesuai target
- jumlah bullet sesuai target
- bahasa dokumen sesuai pilihan
- tone sesuai pilihan
- template/theme sesuai pilihan
- section include/exclude diterapkan
- section order benar
- target region memengaruhi format/tone
- filename sesuai konfigurasi
- output disimpan sebagai versi baru jika diminta
- konfigurasi tersimpan sebagai configSnapshot

Jika user meminta hal yang tidak ideal, sistem tetap harus memberi warning, bukan diam-diam mengabaikan. Contoh: CV ATS 10 halaman harus diberi warning bahwa ini berisiko tidak ATS-friendly untuk early-career.

2. CONTENT VALIDATION
Pastikan isi artifact benar:
- nama, email, phone, location, link, education, experience, skill, dan data user tidak salah mapping
- tidak ada placeholder seperti “Lorem ipsum”, “Your Name”, “[insert here]”
- tidak ada hallucinated claim yang tidak berasal dari UserProfile, context_notes, probing answer, atau input user
- angka/metrik yang muncul bisa ditelusuri sumbernya
- tidak ada repetisi generik berlebihan
- tidak ada buzzword tanpa bukti
- tidak ada section kosong yang tetap ditampilkan
- tidak ada field undefined/null/NaN
- bahasa tidak campur-campur kecuali memang diminta bilingual

3. DOCX VALIDATION
Untuk semua DOCX:
- file harus valid OOXML dan bisa dibuka
- unzip file dan pastikan document.xml ada
- extract text dan pastikan teks selectable
- pastikan heading section terbaca
- pastikan urutan section benar
- pastikan bullet terbaca sebagai teks
- pastikan tidak ada table/textbox/sidebar untuk CV ATS
- pastikan font, margin, dan ukuran sesuai hard constraint
- render/open via LibreOffice atau equivalent jika tersedia
- convert ke PDF preview untuk cek visual jika memungkinkan
- cek tidak ada teks terpotong, overlap, atau spacing rusak

4. PDF VALIDATION
Untuk semua PDF:
- file harus bisa dibuka
- teks harus selectable jika output text-based
- jangan membuat PDF dari screenshot/gambar kecuali user memang meminta visual image PDF
- extract text dan bandingkan dengan preview
- cek jumlah halaman
- cek margin
- cek overflow
- cek font fallback
- cek section tidak terpotong antar halaman secara buruk
- cek link/contact tetap terbaca
- cek ukuran file wajar

5. PPTX VALIDATION
Untuk semua PPTX:
- file harus valid OOXML
- unzip dan pastikan slide XML lengkap
- jumlah slide harus sesuai konfigurasi
- extract text dari semua slide
- pastikan tidak ada placeholder
- pastikan tiap slide punya title dan content yang sesuai
- render PPTX ke PDF/image preview via LibreOffice/Impress/headless jika tersedia
- cek visual tiap slide: tidak overflow, tidak ada teks kepotong, tidak ada elemen tabrakan, tidak ada font fallback aneh, tidak ada object keluar canvas
- cek semua template/theme yang tersedia, bukan hanya default

TAMBAHAN WAJIB — TOEFL/IELTS 2026-READY TEST SPEC, SCORING, AND ITEM QUALITY ENGINE

Sebelum membuat atau mengubah modul English Practice, lakukan audit resmi terhadap format TOEFL iBT terbaru dan IELTS terbaru dari sumber resmi ETS, IELTS.org, British Council, IDP, dan Cambridge English jika diperlukan. Catat hasil riset singkat di worklog.md. Jangan mengandalkan asumsi lama karena TOEFL iBT mengalami update mulai Januari 2026.

Bangun sistem sebagai TOEFL/IELTS-oriented practice system, bukan official TOEFL/IELTS clone. Jangan memakai, menyalin, menyadur, atau scrape konten resmi/copyrighted dari ETS, IELTS, British Council, IDP, Cambridge, Magoosh, BestMyTest, Kaplan, Barron’s, atau prep site lain. Semua passage, transcript, audio, soal, opsi jawaban, answer key, explanation, dan distractor rationale harus original.

1. TEST SPEC VERSIONING

Buat sistem TestSpec yang versioned dan configurable, minimal:

- TOEFL_IBT_2026
- TOEFL_IBT_LEGACY_COMPAT
- IELTS_ACADEMIC
- IELTS_GENERAL_TRAINING
- LARAS_TOEFL_STYLE_PRACTICE
- LARAS_IELTS_STYLE_PRACTICE

Setiap TestSpec wajib menyimpan:

- test family
- section: reading, listening, structure/grammar, speaking, writing
- target format
- difficulty scale
- CEFR mapping
- scoring scale
- question count rule
- timing rule jika ada
- question type distribution
- skill tag distribution
- topic distribution
- allowed item types
- scoring method
- explanation requirement
- validation rule
- lastReviewedAt
- sourceNotes di worklog.md, bukan konten copyrighted

TOEFL 2026 harus mendukung:
- score scale 1–6 dengan increment 0.5
- CEFR-aligned interpretation
- comparable 0–120 estimate selama masa transisi, tetapi labeli sebagai “estimated/comparable practice score”, bukan official score
- adaptive practice behavior
- modern academic + real-life campus topics
- faster, more personalized practice flow

IELTS harus mendukung:
- band scale 0–9
- half-band reporting
- raw score to estimated band untuk Listening/Reading
- Academic Reading vs General Training Reading distinction
- Writing/Speaking rubric-style feedback berdasarkan kriteria IELTS, tetapi labeli sebagai practice estimate, bukan official band

2. QUESTION BLUEPRINT ENGINE

Jangan generate soal secara bebas tanpa blueprint.

Buat QuestionBlueprint untuk setiap set yang menentukan:

- testSpec
- section
- difficulty
- CEFR target
- topic domain
- context type
- passage/transcript length
- vocabulary level
- sentence complexity
- question count
- skill tag distribution
- distractor strategy
- expected time to complete
- scoring weight
- explanation depth
- uniqueness constraints

Contoh untuk TOEFL-style Listening:
- 1 main idea question
- 2 detail questions
- 1 inference question
- 1 speaker attitude/purpose question
- opsional 1 organization/function question
- semua jawaban benar harus didukung transcript
- distractor harus plausible tetapi jelas salah jika user memahami audio

Contoh untuk TOEFL/IELTS-style Reading:
- main idea
- detail
- inference
- vocabulary-in-context
- author purpose
- rhetorical function
- sentence simplification jika cocok
- semua jawaban benar harus bisa dilacak ke kalimat/paragraf tertentu

Contoh untuk Structure/Grammar:
- grammar tag wajib jelas
- hanya satu error/target structure utama
- explanation harus menyebut aturan grammar
- hindari kalimat ambigu yang punya lebih dari satu jawaban benar

3. AI ITEM WRITER QUALITY PIPELINE

Saat production generate soal on-the-go, jangan langsung tampilkan output LLM. Buat pipeline minimal:

STEP 1 — Blueprint selection
Sistem memilih blueprint berdasarkan:
- testSpec
- target user
- kelemahan user
- history user
- difficulty adaptif
- topic rotation
- section target

STEP 2 — Draft generation
LLM membuat passage/transcript/questions berdasarkan blueprint.

STEP 3 — Self-critique
LLM kedua atau pass kedua melakukan review:
- apakah hanya ada satu jawaban benar?
- apakah jawaban benar didukung teks/audio?
- apakah distractor terlalu mudah?
- apakah ada opsi duplikat?
- apakah explanation akurat?
- apakah soal bisa dijawab tanpa membaca/mendengar?
- apakah level bahasa sesuai CEFR/difficulty?
- apakah topic terlalu mirip dengan latihan sebelumnya?
- apakah ada copyrighted-looking content?
- apakah ada konten sensitif yang tidak perlu?

STEP 4 — Deterministic validation
Kode melakukan validasi non-LLM:
- schema valid
- jumlah soal benar
- pilihan A-D lengkap
- answerKey valid
- tidak ada duplicate options
- tidak ada empty passage/transcript
- word count sesuai range
- duration/audio metadata valid
- skill tags valid
- difficulty valid
- explanation tidak kosong
- storagePath valid jika audio
- checksum/hash ada jika file audio
- no placeholder text
- no undefined/null/NaN

STEP 5 — Evidence grounding check
Untuk reading/listening:
- setiap question wajib punya evidence pointer:
  - passage paragraph number atau sentence id
  - transcript timestamp atau line id
- answer explanation harus merujuk evidence pointer
- jika evidence pointer tidak ada, item invalid

STEP 6 — Quality score
Setiap generated set diberi itemQualityScore 0–100 berdasarkan:
- blueprint adherence
- uniqueness
- difficulty match
- answerability
- distractor quality
- explanation clarity
- evidence grounding
- language naturalness
- audio validity untuk listening

Jika score < 80, jangan tampilkan ke user. Regenerate atau kirim ke review queue.

4. SCORING SYSTEM

Bangun scoring engine yang jelas dan tidak menyesatkan.

Untuk practice mode:
- tampilkan raw score
- percentage
- skill breakdown
- weakness tags
- estimated CEFR
- estimated TOEFL 1–6 practice score jika TOEFL spec
- estimated comparable 0–120 practice score jika TOEFL legacy compatibility aktif
- estimated IELTS band jika IELTS spec
- confidence level: low/medium/high berdasarkan jumlah item dan konsistensi performa

Jangan menyebut hasil sebagai official TOEFL/IELTS score. Pakai label:
- “Estimated practice score”
- “TOEFL-style practice estimate”
- “IELTS-style practice band estimate”
- “Not an official score”

Untuk mini practice 5–10 soal, confidence harus low/medium, bukan seolah-olah akurat seperti full test.

Untuk full mini test, confidence boleh lebih tinggi, tetapi tetap estimated.
